# Saved Reports and Original Archives Closeout

Date: 2026-11-26. **Subphase 5F.4 Complete.**

## Delivered Scope

Extraction can save report, uploaded-file and paste captures with required
source metadata, indicator mentions and literal citation edges. Version 2
of the shared evidence schema adds atomic save manifests, separate archive
availability and normalized bulk lookup results. Legacy tables/date meanings
remain unchanged. Unknown sources remain F, unreviewed and disabled.

Save identity binds input bytes, metadata, parser output/version and capture
identity. Changed input creates another capture. Replays preserve original
collection time, source publication/modification/observation dates, originating
execution and later citation resolution. Report fetches retain the actual
entity bytes before normalization; saving does not fetch again. The source
reference and final captured record reference remain distinct where needed.
Mentions do not establish maliciousness or independent corroboration.

Original storage defaults off. It requires explicit positive finite response,
per-source, total-byte and retention-age limits and a private root below the
configured ignored data directory. Generated paths, reserved capacity, an
OS-held archive lock, exclusive temporary writes, fsync/atomic rename and
paged reconciliation preserve honest pending/stored/omitted/expired/failed
states. Expiry and missing/partial/corrupt originals preserve evidence history
and digests. Read/list availability expires before physical cleanup.

Approved startup can run bounded verification and local maintenance pages.
The runtime maintenance loop continues recovery/expiry without network
collection. Health reports failures and page progress. Unknown/sensitive or
restricted-TLP material is omitted from raw storage and excluded from bulk
submission. Common credential patterns and configured key values are guarded.
There is no raw render/download/export route, encryption or quarantine system.
Explicit per-source public handling is separate from collection approval.

Enrich All splits up to 2,000 mentions into jobs of at most 10 enrichable
indicators. Keyless units precede explicitly selected additional providers
within each batch. Provider source review, private-IP/Tranco/hashlookup gates,
finite requests/bytes/time/attempts, rolling quotas, 429 cooldowns, cancellation
and rechecks apply to units, retries and resumption. The worker defaults off.
Jobs use the same application loop, HTTP client, provider limiter and database
execution lock as existing feeds. No event loop is created per job.

Fixed code owns provider destinations. RDAP redirects permit only the finite
proposed Verisign/PIR and five RIR route patterns, with quota and eligibility
checks on each hop. Unknown destinations are refused. These are opt-in policy
proposals requiring review before enabling, not fresh endpoint/terms findings.
Equal response bytes from different request inputs get separate capture slots.
Successful normalized provider attributes retain source/capture/report links;
cached results retain query time and do not claim a new original capture.

## Limits and Boundary

See [Runbook](../runbooks/saved-reports-and-archives.md) for exact commands,
limits, activation gates and handling/retention semantics. List/history views
are bounded. One operator, app/database and local filesystem are supported.
Filesystem/CPU deadlines are cooperative. Deletion while the app is stopped
waits for restart or approved manual maintenance. Keep root/limits configured
when disabling new writes if automatic cleanup should continue. Changing root
does not move or maintain the old root automatically. Labels and scanners are
not encryption, access controls or a universal secret detector.

Non-200 provider bodies are discarded. Ordinary one-IOC manual lookups retain
their previous cache contract and are not retroactively original archives.
Exhausted jobs remain failed/incomplete; terminal work is not reset on replay.
History has no pruning. Sensitive retention/privacy deletion, arbitrary RDAP
registry expansion and live source acceptance need separate work. Alerts and
foundation integration acceptance are 5F.5. Collectors and AI remain later.
