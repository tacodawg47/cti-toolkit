## Delivered Scope

One API-only GitHub public-code metadata consumer reuses the existing app
event loop, httpx client, GitHub limiter, durable scheduler/jobs, evidence
and local inbox. It adds no dependency, SDK, separate worker or event loop.
Existing Phase 2 GitHub repository/README and advisory behavior is preserved;
the new consumer never calls those content-fetch methods. Only the fixed
GET /search/code surface is permitted. Returned links, redirects, code,
blobs, repositories, READMEs, profiles and secret endpoints are never fetched.
No found credential becomes another query or a validity test.

The dated [API Review](../research/2026-11-27-github-exposure-api-review.md)
records the current search overview/complete code endpoint, legacy syntax,
authentication, versions, pagination, quotas and full primary terms/AUP.
Privacy and pricing were reviewed with checked/unchecked coverage stated.
No GitHub repository/tool code was imported. Historical shared clients and
source catalog candidates were revisited, not automatically adopted.

Real access gap: the current code endpoint requires authentication in its
prose but its generated public-resource section claims anonymous access.
It lists fine-grained token support without permissions; this was not
verified against a real account. The consumer requires a separate token
whose public-only access a human has reviewed, plus a default-false local
attestation. It never inherits a potentially private-capable Phase 2 token.
The attestation is not proof of scope or entitlement. Operator-specific
terms/purpose, privacy/removal handling, token support and actual schema
still need separately approved measured live acceptance. Registry terms and
collection remain unapproved. No account or token was created or tested.

At most ten explicit github_domain/github_organization selectors have
separate expiring submission permissions. Domains canonicalize with strict
IDNA2008; organization text uses bounded plain ASCII. No aliases, inferred
GitHub owners, fuzzy/permutation expansion, regex or qualifier injection.
Queries contain only the quoted exact canonical selector and in:file.
Legacy punctuation semantics cannot prove an exact content occurrence.
Dedicated observations therefore record provider query attribution, not a
confirmed domain occurrence, organization identity or ownership assertion.
A metadata hit is a review lead, not proof of exposure, secret validity or
maliciousness. No generic domain/organization hit is inferred.

Permission snapshots bind exact selector type/value/query, query/API versions,
and the reviewed token digest. Changed token, version or selector definition,
revocation, expiry, suppression and selector/source/schedule disabling stop
new work at cooperative unit, quota, request, stream, parse, stage and
ingestion boundaries. A renewed permission never replaces queued authority.
Empty plans remain empty. Suppression stops future submission, not evidence
history or privacy deletion. No web form dispatches collection or grants it.

Each immutable plan has two fixed page slots per query. Page 2 is used only
when the first page reports over 50 results. Validated allowlisted metadata
is staged under its original capture/document/run. Assertions, literal
citations, inbox matches and page completion commit atomically. Restart
uses saved input and skips committed pages. A finalization crash repairs
query progress without a refetch or review reset. Generic capture progress
has an explicit consumer-owned logical-unit option; existing feeds keep
their default. Terminal failed/cancelled staging is not adopted by another
daily scope. New daily passes make new acquisitions.

Stable provider repository-ID/file-path events retain inbox reviews across
blob revisions, repository renames and captures. Independent query selectors
keep their own alerts, source captures and unknown dates. Local catch-up
matches only saved query attribution, never another inferred entity.

Only repository ID/full name, file path, blob SHA and a validated literal
html_url survive. Source/file publication, modification, observation and
first/last-seen dates stay unknown. Repository/HTTP dates do not substitute.
Literal references are unresolved passive text, never constructed as supplied
citations or visited. Blob SHA is not a commit/file timestamp. Sensitive
captures force raw omission even under generic public archive settings.
Queries and authorization headers are absent from capture/job metadata;
private permission records retain the approved query. Provider errors/bodies
and credential values never enter job logs. Unknown descriptions, dates,
profiles and fields are discarded; unexpected content-bearing results fail.

One daily schedule with a two-day stale threshold brings the composed
catalog to 35. All schedules, workers, bulk and raw storage default off.
Per-selector age uses the oldest original page capture in the last
consistent bounded window. Provider-incomplete, truncated, drifting,
duplicate or short pages retain leads but do not renew success. Global pass
dates are separate. Never Loaded, Stale, Failed and Incomplete stay visible
with earlier evidence and reviews. All GET pages are passive.

## Bounds and Operational Limits

Per attempt: 20 requests, 40 MiB charged allowance, 120 seconds for new work.
Per response: 2 MiB, 30 seconds including streaming, identity encoding only.
Per query: two 50-item pages, 256 KiB normalized input per page. Three total
attempts. Local rolling limits: 8/minute and 48/day in the shared scheduled
GitHub bucket, plus the existing app-loop limiter. Numeric Retry-After and
zero-remaining/reset headers persist bounded cooldowns; all 403s conservatively
back off, including possible access denials. No token rotation or fallback.
Other applications/manual routes are not governed by this rolling ledger.
In-flight requests cannot be retracted; parsing/committed SQL can finish
past a soft deadline. Database transactions never span network requests.

Coverage is bounded query windows, not an atomic provider snapshot, exact
literal content verification, continuous monitoring or complete history.
Search/index restrictions can hide results. Even consistent counts do not
prove indexing completeness. No result establishes credential validity,
ownership, exposure or maliciousness. Some valid Unicode/encoded path and
branch references fail the deliberately narrow metadata policy. Common
credential guards are not universal secret recognition. No privacy deletion,
encryption, export or history pruning is added. Metadata stays private/local.

No provider search/data request, selector submission, source enabling, live
migration/restart, install, historical reload or Git operation occurred.
The live database remains unmigrated/unrestarted for 5F.1 through 3A.4.
Linux, native-browser visuals and live v1 acceptance remain unperformed.
Approve real access/handling/exact disclosure, migration/restart and small
measured schema/quota/freshness/recovery acceptance separately. See
[Runbook](../runbooks/github-exposure.md). Collection remains off.
