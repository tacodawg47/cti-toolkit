## Design Decisions and Limits

Use the existing Python/SQLite/pydantic stack without dependencies. Add
separate job tables and a version ledger, leaving source-specific queues,
manual routes and async rate-limit behavior unchanged. Core startup creates
tables but neither registers nor dispatches jobs. Later async consumers must
invoke the synchronous API through a worker thread.

The first focused run passed all 20 initial runner tests, then exposed the
existing fresh-file WAL initialization race in shared compatibility. Added a
bounded BUSY/LOCKED-only startup retry and a regression for deadline/non-lock
errors. Further review reused the shared eligibility gate within runner
connections and prevented progress from erasing a known total. Expanded to
24 runner cases. The first full suite passed 549 tests with one skip; it was
superseded by the final 553-test run after these refinements. The installed
venv launcher required execution outside the managed sandbox restriction.
No environment setting or installed package changed.

Execution is serial per canonical local database path. A process-held lock
avoids reclaiming a live slow handler through lease expiry. A hung handler
blocks other runner jobs until it ends; bounded requests and cooperative
checks are required. Cancellation does not kill threads or retract requests.
No detached handler work, distributed worker, network filesystem or database
hard-link alias support. Windows process/thread paths were executed. Linux
uses stdlib flock but was not executed on this Windows host.

This is at-least-once recovery after an interrupted attempt, with active
duplicate-execution exclusion and idempotent evidence replay. It does not
promise exactly-once arbitrary external effects. A source adapter must verify
the original input/revision/digest before replaying writes under saved capture
metadata. The runner does not save raw bodies, prove upstream completeness,
enforce provider quotas or implement global source freshness. Failed and
cancelled work has no generic reset switch. New scopes need new work keys.

Per-job JSON and capture budgets are enforced. Job history is retained and
has no pruning yet. Credentials and response bodies are excluded from job
errors; only fixed error codes are stored. Callers must also keep secrets and
raw data out of parameters/checkpoints. Existing opaque document run IDs are
preserved without retroactive FK/backfill; new runner captures refer to a
retained actual originating run. Current source review/audit/expiry limits
from 5F.1 remain.

Scheduled feed refresh, quotas/async bridging and source health are 5F.3.
Saved reports/archives are 5F.4; alerts are 5F.5. Collectors and AI remain
outside this pass. V1 operational freshness acceptance is still outstanding.
