## Delivered Scope

One opt-in RansomLook recent-100 API consumer feeds shared evidence and the
existing local inbox. `/ransomware` lists saved claims and paged immutable
capture history. Watches and revision-checked reviews use `/alerts`.
The app composes this registration with the existing 31 feed surfaces; all
32 schedules and the worker default off. Existing manual providers remain
unchanged. No new dependency, service-code import, collector or AI.

The current [Source Review](../research/2026-11-26-ransomware-api-review.md)
records the source's full About/API/schema review, data attribution and
service-code license separately. RansomLook data is credited under its
declared CC BY 4.0 terms. Raw bodies are forced omitted because Post responses
can include encoded HTML and screenshots. The adapter retains only bounded
group/title/discovery/website/reference metadata. ransomware.live victim
integration is deferred because its current own documentation/terms could
not be verified; the browser explicitly blocked its documentation and no
workaround followed. Historical reviews do not approve current integration.

Organization watches compare exact normalized titles with Unicode NFKC,
case folding and whitespace collapse. Punctuation is significant. Country
uses explicit two-letter codes; sector uses explicit normalized labels.
No aliases, fuzzy names, cross-type expansion or inferred classifications.
RansomLook's documented Post schema supplies no sector or country. These
remain unknown; synthetic normalized fixtures exercise those watch types
end to end. Several watches are independent matches, not a combined filter.

Source plus group plus exact literal title identifies a claim. Renamed titles
become new claims. Separate captures and their reported observations remain
immutable evidence. Optional trusted inbox event keys deduplicate by selector,
source claim and subject type, preserving the original alert and review.
Generic evidence retains per-observation alert semantics. Capture history
links later sightings without suggesting independent corroboration.

Each request has a persisted original digest, collection time and originating
run before ingestion. Validated normalized input has a bounded durable queue.
Claim/capture associations, observations, citations, matches and row cursor
commit together. Resumption drains saved input before fetching a changed
snapshot. Failed terminal batches remain recoverable; cancelled queues are
retained but excluded from automatic resumption. Raw omission/expiry cannot
erase committed metadata or staged normalized rows. Attempts, retrieval,
ingestion and scoped coverage remain distinct.

Discovery remains a literal source field and, when its precision/timezone
permits, a separate source observation date. It is not attack/publication
time. Missing dates stay null. Literal cited references stay passive, with
explicit local resolutions displayed separately. Originating interrupted
executions and later successful logical jobs remain distinct.

## Limits and Boundary

Coverage is latest 100 posts per retrieval only. Historical completeness,
continuous gap-free monitoring, taxonomy mapping and corroboration are not
assessed. Current means a recent scoped snapshot succeeded, not that no posts
were missed during downtime. Title renames may produce another alert.
No automatic large historical reload, raw-body retention, history pruning,
privacy deletion or organization-alias lifecycle is delivered.

No live source enabling, provider API data request, migration, app restart,
dependency installation or external private-data transfer occurred. Public
documentation was read through research tools. The live database remains
unmigrated/unrestarted for 5F.1 through 3A.1. Linux, native-browser visual,
live source schema/size/quota and v1 operational acceptance remain unperformed.
